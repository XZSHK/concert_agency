# Концертно-гастрольное и билетное агентство «Арт-Престиж»

**Вариант 30. Индивидуальная карточка задания № 30. Шифр: КТЗ | Группа: ПР-23 | Профессиональный модуль: ПМ.01**

Организация гастролей музыкальных коллективов, аренда залов, выполнение райдеров и билетная программа.

## Технологии

- **C# (.NET 10)**, **Avalonia UI** (кроссплатформенный UI, открывается в Visual Studio)
- **MySQL** (база `Concert_Agency`, 7 таблиц по ТЗ) — пакет `MySql.Data`
- **QRCoder** — QR-код электронного билета
- **xUnit** — модульные тесты (ПК 1.4)

## Как запустить в Visual Studio

1. Установите **Visual Studio 2022** (17.x) с нагрузкой «Разработка классических приложений .NET» и **MySQL Server** (локально).
2. Откройте **`Avalon.sln`** в Visual Studio.
3. Используйте существующую БД `Concert_Agency`. Приложение не создаёт и не пересоздаёт таблицы автоматически; структура должна соответствовать используемым приложением таблицам и полям, описанным ниже.
4. Строка подключения по умолчанию: `Server=localhost;Database=Concert_Agency;Uid=root;Pwd=` (root без пароля, как в исходном проекте).
   Если у вас другой пароль/хост — задайте переменную окружения `CONCERT_DB_CONNECTION`, например:
   `Server=localhost;Database=Concert_Agency;Uid=root;Pwd=ваш_пароль`
5. Нажмите **F5** (или `dotnet run`) — откроется окно входа.

### Вход и регистрация

Используйте учётные записи сотрудников и покупателей, уже заведённые в вашей БД. Проект не добавляет тестовые аккаунты автоматически. Нового покупателя можно зарегистрировать через кнопку «Зарегистрироваться».

### Запуск тестов

В Visual Studio: **Test → Run All Tests**. Из командной строки:

```bash
dotnet test Avalon.sln
```

## Маски ввода и внешний вид

Во всех окнах ввода — маски и валидация (`InputMasks.cs`):

| Где | Поле | Маска |
|---|---|---|
| Регистрация / Профиль | Телефон | `+7 (999) 123-45-67` (автоформатирование, 8→7) |
| Регистрация / Профиль | ФИО | только буквы, дефис и пробелы |
| Создание концерта (продюсер) | Дата и время | `дд.мм.гггг чч:мм` (автоподстановка `.` и `:`) |
| Создание концерта (продюсер) | Цены партера/VIP | только цифры, один разделитель, 2 знака после точки |
| Создание концерта (продюсер) | Возраст | `12+` (цифры + авто-плюс) |
| Фильтр заказов (менеджер) | Дата концерта | `дд.мм.гггг`, автофильтрация таблицы |

Дополнительно: кнопки действий в заказах включаются/отключаются автоматически по FSM; переход осуществляется только по легальной цепочке; в окне брони лайт-таймер (красный в последнюю минуту); закрытие окна без оплаты отменяет бронь; список карточек концертов подгружает картинки из папки `img/` (копируется в вывод сборки при каждой сборке), с предпросмотром в форме создания концерта. Афиши везде вписываются в рамку целиком (`Stretch="Uniform"`, без обрезки): на карточках афиши покупателя и в герой-баннере бронирования; в окне брони баннер можно масштабировать колесиком мыши или кнопками − / + (нажатие на процент сбрасывает масштаб). В форме концерта у продюсера есть слайдер «Отдаление (масштаб)», слайдер «Размер кадра (высота)» и переключение режима кадра «Вписать / Заполнить» для живого предпросмотра. В форме концерта файл афиши можно **перетащить мышью прямо в рамку предпросмотра** — он скопируется в папку `img/` проекта и его имя сохранится в `concert_events.image_path` (при редактировании существующего концерта — сразу, при создании нового — вместе с INSERT); если столбец `image_path` отсутствует, программа работает без него (падения не будет).

## Реализация ТЗ

### Дополнительные концерты и афиши

В `img/` добавлены афиши вымышленных коллективов (имена в свободном использовании): «Северное сияние» (альт-рок), «Мята Лемон» (инди-поп), «Анна Волкова» (поп), «Монтевидео» (джаз-квинтет), «TIDAL ECHO» (электроника), «Зимняя сказка» (симфонический оркестр). Скрипт `add_concerts.sql` вставит 6 концертов (даты 05.12.2026–30.01.2027) в `concert_events` и идемпотентен; залы назначаются по кругу из первых занятых залов (можно заменить на свои id). Выполните его один раз в phpMyAdmin. Постеры копируются в вывод сборки вместе с остальными картинками `img/`.

### База данных (7 таблиц MySQL)

Приложение использует существующую БД `Concert_Agency` и таблицы `roles`, `users`, `concert_halls`, `concert_events`, `ticket_buyers`, `ticket_orders`, `ticket_order_seats`. Скрипта создания или пересоздания схемы в проекте нет. Для входа покупателей код ожидает поле `ticket_buyers.password`; для афиш — `concert_events.image_path`.

**Онлайн-заказы покупателя и `ticket_orders.user_id`.** Заказ покупателя привязан к `ticket_buyers` через `buyer_id`. Столбец `user_id` (сотрудник, оформивший продажу) в исходном дампе `NOT NULL`, поэтому онлайн-заказ оформляется от технического аккаунта с ролью «Клиент». Выполните один раз в phpMyAdmin (скрипт идемпотентен):

```sql
-- 1) Роль «Клиент» (если её ещё нет)
INSERT INTO `roles` (`name`)
SELECT 'Клиент'
WHERE NOT EXISTS (SELECT 1 FROM `roles` WHERE `name` = 'Клиент');

-- 2) Технический аккаунт онлайн-канала (войти под ним невозможно/незачем)
INSERT INTO `users` (`role_id`, `login`, `password_hash`, `full_name`)
SELECT r.id, 'client', SHA2('online-channel-internal', 256), 'Клиент (онлайн-заказ)'
FROM `roles` r
WHERE r.name = 'Клиент'
  AND NOT EXISTS (SELECT 1 FROM `users` WHERE `login` = 'client');
```

Альтернатива без технического аккаунта — разрешить пустое значение: `ALTER TABLE \`ticket_orders\` MODIFY \`user_id\` int(11) NULL;` (вставка без `user_id` и так поддержана в коде). Заказ из кассы сотрудника всегда подставляет в `user_id` его id.

### Бизнес-логика и расчётная формула (`Core/OrderCalculator.cs`)

```
final_seat_cost = base_seat_price + (сектор VIP ? 500 руб. бейдж : 0)
service_fee     = has_promo_subscription ? 0 : 10% от стоимости заказа
total_amount    = Σ final_seat_cost + service_fee
```

Пример: 2×Партер 1500 + 1×VIP 3000 → 6500 + 650 (10%) = **7150 руб.**; с промокодом — **6500 руб.**

### Жизненный цикл заказа — конечный автомат FSM (`Core/OrderStateMachine.cs`)

```
'Бронь (15 мин)' → 'Оплачен' → 'Выписан' → 'Контроль на входе пройден'
'Бронь (15 мин)' / 'Оплачен' / 'Выписан' → 'Возврат билета' (если до концерта ≥ 24 ч)
```

- Недопустимый переход и редактирование закрытого документа бросают **`InvalidOperationException`**.
- **Возврат заблокирован менее чем за 24 часа** до концерта.
- Квоты по секторам проверяются при брони: занятые места считаются по заказам (кроме возвращённых), места раскладываются по 20 в ряду.
- **Запрещено переводить пустой заказ (0 строк) в статус «Оплачен»** — проверка в `OrderService.ChangeStatus`.
- Операция отмены/возврата заказа требует причины **не короче 10 символов** — вводится через модальный диалог (`CancelReasonDialog`), сохраняется в `cancel_reason`.
- Редактирование позиций документа разрешено только в статусе **«Бронь (15 мин)»** (`OrderService.AddSeat`/`RemoveSeat`, сервисная проверка `EnsureBooking`); оплаченные и закрытые документы — только для просмотра.

### Таймер (`BookingWindow`)

`DispatcherTimer` — обратный отсчёт **15:00** после оформления брони. Если оплата не завершена за 15 минут, заказ переводится в «Возврат билета» с причиной «Бронь истекла (15 мин)» и места освобождаются.

### Главный экран заказов менеджера и экран «Документ» (Master-Detail)

`ManagerDashboardWindow`: живой поиск по номеру/покупателю/концерту, фильтры по статусу и дате концерта, **сортировка по столбцам** (клик по заголовку), **цветовая индикация** строк (бронь — жёлтым, возврат — красным, контроль пройден — зелёным). Кнопка **«Документ»** открывает `OrderDetailsWindow` — полные реквизиты заголовка заказа + встроенный DataGrid строк спецификации. Итоги (позиции, сумма мест, сервисный сбор, итого) пересчитываются привязками на лету. Позиции можно добавлять/удалять только в статусе «Бронь (15 мин)»; удаление подтверждается модальным диалогом; итоги документа (`service_fee`, `total_amount`) пересчитываются в БД транзакционно; сервисный сбор обнуляется для подписчиков промокодов.

### Окно входа

Маска пароля `*` с кнопкой-глазиком (показать/скрыть) в `MainWindow` и `RegisterWindow`. После **трёх** неверных попыток входа интерфейс блокируется на **10 секунд** с визуальным обратным отсчётом (`DispatcherTimer`).

### Номер документа (`Core/DocumentNumber.cs`)

Маска ТЗ: **`PR23-KTZ-{Год}-{Номер:D5}`**, например `PR23-KTZ-2026-00042`. Следующий номер вычисляется по максимальному существующему в БД за текущий год.

### Экспорт билета и подпись (`Services/TicketExportService.cs`, `Core/TicketSignature.cs`)

Кнопка «Скачать билет (QR)» сохраняет в `Документы\ArtPrestigeTickets\`:
- `ticket_{номер}.txt` — электронный билет: QR-нагрузка, схема прохода в сектор, правила безопасности;
- `ticket_{номер}_qr.png` — QR-код.

Цифровая подпись **SHA256** от конкатенации `[Номер]+[Дата]+[Контрагент]+[Сумма]+[КоличествоПозиций]` печатается в билете и зашита в QR-код. Проверка — `TicketSignature.Verify(...)`.

### Пароли (`Core/PasswordHasher.cs`)

`users.password_hash` хранит SHA256-хэш. Вход принимает и хэш, и старый открытый пароль (обратная совместимость с уже существующей БД); новые регистрации сохраняются сразу хэшем.
